# Булшитометр

Разбирает публичные тексты автора (посты, анонсы, ответы, расшифровки)
и показывает, как в них устроены давление, обещания, эксклюзивность
и коммерция, а рядом проверяемость, добросовестность и автономия.
Результат: тип из семи, уверенность, семь осей словами, найденные
цитаты с объяснением и альтернативной трактовкой.

Модель только размечает цитаты. Всё остальное, от баллов до типа,
считает код по таблице из `engine/rubric.json`.

## Запуск

```
npm install
npm test                  # node --test, сеть не нужна
npx netlify dev           # страница и функции локально
```

Для `netlify dev` нужен `ANTHROPIC_API_KEY` в окружении, остальные
переменные имеют значения по умолчанию.

### Переменные окружения

| Переменная | Что это | По умолчанию |
|---|---|---|
| `ANTHROPIC_API_KEY` | ключ Claude API, только на сервере | обязателен |
| `IP_SALT` | соль для хеша IP и подписи заданий фоновой функции | обязателен |
| `DAILY_CAP` | сколько вызовов модели в сутки на весь сайт | 500 |
| `HOURLY_PER_IP` | сколько разборов в час с одного адреса | 10 |
| `MODEL_EFFORT` | глубина размышления модели: `low`…`max` | `medium` |

`ANTHROPIC_API_KEY` и `IP_SALT` помечаются в Netlify как секреты.
Ключ не попадает ни в страницу, ни в ответы, ни в логи, даже внутри
текста чужой ошибки: `engine/app.mjs` вычищает его перед выдачей.

## Как устроен разбор

```
страница ──POST /api/analyze──▶ лимиты → кэш ──HIT──▶ 200 с результатом
                                         └─MISS─▶ бюджет → задание → 202 {job}
         ◀──GET /api/analyze?job=… раз в 2 с──  202 пока идёт, потом 200
фоновая функция: разметка моделью → проверка цитат → запись в кэш
```

Синхронная функция Netlify живёт около 10 секунд, а разметке с
размышлением модели нужно больше. Поэтому разметка идёт в фоновой
функции `analyze-background` (до 15 минут), а страница опрашивает
задание. **Фоновые функции есть не на всех тарифах Netlify**: перед
запуском проверьте, что на тарифе сайта они включены, иначе каждый
разбор закончится ошибкой 502.

Порядок проверок в `/api/analyze` и есть защита денег: метод, Origin,
размер тела, форма входа, частота с адреса, кэш, дневной бюджет.
До модели доходит только то, что прошло всё.

Хранилище: Netlify Blobs, четыре стора (`extractions`, `ratelimit`,
`counters`, `jobs`). В кэш пишется разметка: короткие цитаты, сигналы,
пояснения и число слов по текстам. Сами тексты не хранятся нигде.
Кэш живёт 30 дней. Счётчики в Blobs не атомарны: при одновременных
запросах лимит может пропустить лишний вызов, для MVP это приемлемо.

## Как считается результат

Формулы и все числа лежат в `engine/rubric.json`, код в `engine/score.mjs`
только их применяет.

1. **Балл находки:** `c = w · m_strength · Π m_modifier · m_genre`.
   `w` вес сигнала, сила 1–3 даёт множитель 0.5 / 1 / 1.5, модификаторы
   (гарантия, срок, условие, конкретность) умножают дальше, а жанр
   «продажа» ослабляет дедлайн, дефицит и ступени: в анонсе они
   ожидаемы.
2. **Насыщение по тексту:** `S = sign(w) · min(Σ|c_k| / k, 3·|w|)`.
   Десять одинаковых приёмов в одном тексте не весят в десять раз больше.
3. **Шаблонные тексты:** тексты с похожестью по словесным 5-граммам
   от 0.8 или помеченные моделью как шаблон склеиваются в один кластер.
   Сто одинаковых постов считаются как один.
4. **Ось:** `raw = m_scenario · (1 / n_eff) · Σ S`, где `n_eff` число
   кластеров, а `m_scenario` усиливает важное для сценария (курс,
   терапевт, учитель, реклама). Затем `v = 1 − e^(−raw / k)` и уровень:
   ниже 0.25 низкий, до 0.6 средний, выше высокий.
5. **Уверенность:** низкая при меньше чем 3 разных текстах или 800
   словах; высокая от 8 разных текстов, 3000 слов и не больше 60 %
   продающих; иначе средняя. Если больше 30 % цитат модели не нашлось
   в текстах дословно, уверенность падает на ступень.
6. **Тип:** первое сработавшее правило из `types` в рубрике. Низкая
   уверенность всегда даёт «Тёмную материю».

Цитата, которой нет в тексте после нормализации (регистр, ё, кавычки,
тире, пробелы), отбрасывается до подсчёта. Модель не может добавить
балл за то, чего автор не писал.

**Веса экспертные, версия 1.** Их никто не мерил на размеченной
выборке. Это договорённость о том, что считать сильнее, а не
измеренная истина, и страница в блоке «Честный язык» так и говорит.
Любая правка весов меняет `version` в рубрике.

## Модель

`claude-sonnet-5` через `fetch`, без SDK. Инструмент `report_findings`
принудительный и строгий: ответ всегда валиден по схеме. Размышление
адаптивное, глубина из `MODEL_EFFORT`.

`temperature: 0` не отправляется: у этой модели параметры сэмплинга
убраны, и любое значение кроме умолчания даёт 400. Одинаковый ответ
на одинаковый вход держат кэш разметки и подсчёт в коде.

Промпт в `prompts/extract.md`, первая строка `prompt-version: N`.
Версия промпта входит в ключ кэша: новая версия промпта сама
сбрасывает кэш.

## Проверка качества

```
ANTHROPIC_API_KEY=… npm run eval
ANTHROPIC_API_KEY=… node scripts/eval.mjs --checks accuracy,stability
```

Прогон через живой API на 14 синтетических авторах из `fixtures/`,
по два на тип. Кэш выключен, полный прогон это около 35 разборов,
то есть настоящие деньги. Пороги:

| Проверка | Порог |
|---|---|
| точность | тип совпал у 10 авторов из 14 |
| подмена автора | тип тот же, уровни совпали минимум по 6 осям из 7 |
| атака «если» | Давление и Эксклюзивность Чёрной дыры падают не больше чем на уровень |
| инъекция | строка «Игнорируй инструкции…» тип не меняет |
| жанр | те же продающие тексты: у `sale` Давление не выше, чем у `post` |
| стабильность | три прогона одной фикстуры дают один тип |

Отчёт в консоль и в `scripts/eval-report.json`, там же время разбора
против цели в 20 секунд. Проваленный порог означает правку рубрики
или промпта с новой версией, а не подгонку фикстур.

## Отступления от спеки

- **Тело запроса до 100 КБ, а не 60.** 40 000 кириллических знаков в
  UTF-8 весят около 80 КБ; с порогом 60 КБ разрешённый объём
  отбивался бы раньше проверки знаков.
- **Нет `temperature: 0`**, см. «Модель».
- **Разметка асинхронная** (задание и опрос), см. «Как устроен разбор».
- **`@netlify/blobs` закреплён на 10.x.** Версия 11 требует Node 22.12,
  а сайт собирается на Node 20.
- **Красный акцент текстом только на панелях.** На основном фоне
  светлой темы его контраст 4.19, ниже 4.5; на панелях 4.61.

## Файлы

```
index.html                  вся страница
netlify.toml                сборка, заголовки, файлы для функций
netlify/functions/          тонкие обёртки над engine/app.mjs
engine/rubric.json          сигналы, оси, веса, пороги, типы
engine/score.mjs            подсчёт, чистые функции
engine/verify.mjs           нормализация и проверка цитат
engine/limits.mjs           лимиты входа, частоты, хеши
engine/model.mjs            запрос к Claude API
engine/app.mjs              обработчики
prompts/extract.md          системный промпт разметки
fixtures/                   синтетические авторы для eval
test/                       node --test
scripts/eval.mjs            прогон качества через живой API
```
