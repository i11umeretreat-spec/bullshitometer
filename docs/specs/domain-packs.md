# Доменные пакеты: движок один, домены файлами

Булшит - это разрыв между заявленным и подкреплённым. Такой разрыв есть не только в продаже курсов: в аннотациях селф-хелп-книг, карточках товаров, вакансиях, описаниях аудиофайлов. Движок у всех один: вытащить утверждения, найти подкрепление, ответить на вопросы до решения. Разные только сигналы, вопросы, тексты и источник подкрепления.

Поэтому универсальным делаем движок, а не продукт. Домен - это пакет данных в своей папке. Второй домен добавляется новой папкой, а не переписыванием кода.

Порядок: эта задача начинается после того, как ветка `slice-1-questions` влита в `main`. Новый домен в неё не входит - только переезд «курсов» в первый пакет.

## 1. Задача

Вынести всё, что знает про домен «курсы и наставники», из кода и общих файлов в пакет `packs/courses/`. Движок, сервер и страница начинают читать пакет по его id. Для пользователя не меняется ни один символ на экране.

## 2. Зачем

Сейчас домен размазан: сигналы и вопросы в `engine/rubric.json`, промпт в `prompts/extract.md`, слова «оплата», «продавец», «курс» прямо в `index.html`. Добавить второй домен в таком виде - значит ветвить код условиями `if (domain === ...)`, и каждый следующий домен будет дороже предыдущего.

После переезда следующий домен - это новая папка с тремя-четырьмя файлами. Проверяем это заранее игрушечным пакетом в тестах: если движок проходит весь путь на пакете, который ничего не знает про курсы, значит, знание про курсы из движка действительно ушло.

## 3. Файлы

Репозиторий `bullshitometer`, ветка `main` после слияния среза 1. Перед правкой сверить, что `main` совпадает с задеплоенным. Если нет - остановиться и спросить.

```
packs/
  courses/
    pack.json          паспорт: id, версия, язык, вид подкрепления, сценарии
    rubric.json        переезжает из engine/rubric.json без изменений внутри
    prompt.md          переезжает из prompts/extract.md без изменений внутри
    copy.json          все строки интерфейса, которые говорят про домен
engine/
  packs.mjs            новый: загрузка и проверка пакета
  score.mjs            читает рубрику из пакета
  answers.mjs          читает вопросы из пакета
  verify.mjs           без изменений
netlify/functions/
  analyze.mjs          принимает domain, берёт пакет
  pack.mjs             новый: GET /api/pack - публичная часть пакета для страницы
index.html             строки домена берёт из /api/pack
test/
  golden/              снимки выходов движка до переезда
  fixtures/packs/demo/ игрушечный пакет, только для тестов
  packs.test.mjs       новый
```

`engine/rubric.json` и `prompts/extract.md` после переезда удаляются, чтобы не было двух источников истины.

## 4. Что меняется

1. Первый коммит - снимки. До любого переезда записать в `test/golden/` выходы движка для всех 14 фикстур: подсчёт, тип, ответы, вопросы продавцу. Находки берутся из подставной модели тестового стенда, так что снимки не зависят от живого API
2. Пакет `packs/courses/`: `rubric.json` и `prompt.md` переезжают как есть, байт в байт. Новые `pack.json` и `copy.json` - по приложению А
3. `engine/packs.mjs` - функция `loadPack(id)`. Читает четыре файла пакета и проверяет перекрёстные ссылки: каждый сигнал в осях, типах и вопросах существует, каждая ось в правилах существует, вид подкрепления поддерживается, в `copy.json` есть все обязательные ключи. Ошибка останавливает функцию при холодном старте с понятным текстом: какой пакет и какой ключ. Загруженный пакет живёт в памяти экземпляра функции
4. `/api/analyze` принимает необязательное поле `domain`, по умолчанию `courses`. Неизвестный домен - 400. В ответе `versions.pack` = `courses@<версия>`. В ключ кэша добавляется id пакета: кэш один раз обнулится, это ожидаемо
5. Новая функция `/api/pack?domain=courses` отдаёт публичную часть пакета: id, версию, тексты из `copy.json`, сценарии и список вопросов с флагом «по умолчанию». Весов и промпта в ответе нет - странице они не нужны. Кэш `public, max-age=3600`
6. `index.html` при загрузке берёт пакет из `/api/pack`. Домен читается из параметра адреса `?domain=`, по умолчанию `courses`. Пока пакет грузится, показываются нейтральные строки оболочки без слов домена. Все строки домена - из `copy`
7. Типы поля: правила уже в рубрике, а названия и строки типов переезжают в `copy.json`. Анимации типов остаются в странице и выбираются по ключу типа. Незнакомый ключ получает нейтральную анимацию звезды
8. Игрушечный пакет `test/fixtures/packs/demo/`: две оси, три сигнала, один вопрос, два типа, свои тексты. Весь путь от находок до ответа проходит на нём в тестах

## 5. Что НЕ трогаем

Это переезд, а не ремонт. Любое видимое изменение - ошибка.

- Тексты на экране, порядок блоков, числа, уровни, типы, ответы и вопросы продавцу - один в один, это проверяют снимки
- Веса, пороги, правила типов и текст промпта: переезжают без правок. Если хочется что-то поправить по дороге - отдельной задачей после
- Лимиты, бюджет, проверка цитат, события метрики
- Второй настоящий домен не делаем. Игрушечный пакет живёт только в тестах и на сайт не попадает
- Переключателя доменов в интерфейсе нет. Параметр `?domain=` - для разработки
- Других видов подкрепления, кроме цитат, не делаем. Измерения для аудио и характеристики для товаров придут вместе со своими доменами
- Первый экран и игру не трогаем

## 7. Ограничения

- Пакет - только данные: JSON и Markdown. Никакого JS внутри пакета. Всё, что пакет «умеет», объявляется данными и исполняется движком
- Один движок на все пакеты. Если для нового домена в движке понадобится `if` по id пакета - это сигнал, что знание не переехало в данные, и формат пакета надо расширить
- Вид подкрепления в этой задаче один - `quote`. Движок отказывается загружать пакет с неизвестным видом, а не пытается угадать
- Ошибки загрузки пакета - по-русски, с путём к файлу и ключу
- Страница остаётся одним файлом, новых зависимостей нет
- Версия пакета - строка в `pack.json`. Любая правка рубрики, промпта или текстов пакета поднимает версию

## Приложение А. Формат пакета

Паспорт `pack.json`:

```json
{
  "id": "courses",
  "version": "1",
  "title": "Курсы и наставники",
  "language": "ru",
  "evidence": { "kind": "quote" },
  "scenarios": [
    { "id": "course", "label": "покупаю курс", "default": true },
    { "id": "therapist", "label": "выбираю психолога" },
    { "id": "teacher", "label": "читаю наставника" },
    { "id": "ad", "label": "проверяю рекламу" }
  ]
}
```

Id сценариев совпадают с ключами `scenario` в рубрике - загрузка это проверяет.

Как решить, куда идёт строка: если она прозвучит странно для книги или карточки товара, она принадлежит пакету. Если одинаково уместна везде - оболочке.

| Где | Что | Примеры |
| --- | --- | --- |
| `copy.json` пакета | вход: заголовок и подпись блока вопросов, подсказка при нуле выбранных, подсказка поля текста, строки ожидания | «Что хочешь понять до оплаты?», «Считаем дедлайны» |
| `copy.json` пакета | результат: заголовки блоков, строка «в пользу» при пустоте, пометка «предварительный», вступление к вопросам продавцу | «Спроси до оплаты», «Здравствуйте! Перед оплатой хочу уточнить несколько вещей:» |
| `copy.json` пакета | типы поля: название, строка, «что проверить» | «Кормушка на орбите» |
| `copy.json` пакета | «Чего мы не знаем» и постоянный пункт адвоката автора | «Мы не видели лендинг, условия возврата и результаты учеников» |
| оболочка в `index.html` | кнопки действий, ошибки 413, 429, 502, 503, «Честный язык», строка карточки | «Разобрать», «Разбор текстов, а не людей» |

Обязательные ключи `copy.json` перечислены в `engine/packs.mjs` одним списком - это и есть контракт пакета. Нет ключа - пакет не загружается.

Вид подкрепления `evidence.kind`:

| Вид | Что подкрепляет утверждение | Статус |
| --- | --- | --- |
| `quote` | дословная цитата из введённого текста | есть |
| `measure` | измерение файла: громкость, спектр, длительность | придёт с аудио |
| `spec` | поле из таблицы характеристик или отзыв | придёт с товарами |

## Приложение Б. Кандидаты в следующие пакеты - не задачи

Это очередь на потом, по близости к тому, что уже есть. Каждый пункт - отдельная спека и отдельная проверка качества.

| Пакет | Что заявлено | Чем подкрепляется | Пример вопроса | Что нужно сделать |
| --- | --- | --- | --- | --- |
| Селф-хелп и нон-фикшн книги | аннотация, обещания метода | `quote` | Чем подкреплён метод? | почти та же рубрика: новые вопросы и тексты |
| Вакансии | «дружная команда», «конкурентная зарплата» | `quote` | Сколько платят на самом деле? | новая рубрика, подкрепление то же |
| Карточки товаров | описание | `spec` | Совпадает ли описание с характеристиками? | разбор таблиц характеристик и отзывов |
| Аудиофайлы | «Hi-Res 24/96», «мастеринг под стриминг» | `measure` | Настоящий ли это Hi-Res? | обработка файлов: спектр и громкость по EBU R128 через ffmpeg. Отдельная инженерия |

Граница для всех пакетов одна: оцениваем разрыв между заявленным и подкреплённым, а не вкус. Хорошо ли написан роман или звучит трек - не наш вопрос.
